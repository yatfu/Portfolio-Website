# Scope of Work

- Do only what the user's prompt requests. Treat the prompt as the boundary of the task, not as a starting point for additional improvements.
- Make the smallest changes necessary to fulfill the request. Do not modify unrelated files, content, styling, behavior, dependencies, or configuration.
- Do not add unsolicited features, refactors, cleanup, documentation, tests, or formatting changes.
- Preserve existing work and user edits outside the requested scope.
- If the request is ambiguous, ask for clarification before making changes based on assumptions.
- If completing the request requires work beyond its stated scope, explain why and obtain permission before doing that additional work.
- Keep inspection and verification directly relevant to the requested change. Do not expand into unrelated audits or fixes.
- Do not commit, push, deploy, publish, or create pull requests unless the user requests it.
- When the requested work is complete, stop and briefly report what changed and any relevant verification or limitations.
